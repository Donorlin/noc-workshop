# AGENTS.md

NoC Organizer – React application built on the NoC platform (`@donorlin/noc-ui`).

## Project context

- [README.md](README.md) – setup, scripts, project layout
- [ARCHITECTURE.md](ARCHITECTURE.md) – features and routing, data loading, API layer, mocks
- [docs/](docs) – [development](docs/development.md), [conventions](docs/conventions.md),
  [API and mocks](docs/api-and-mocks.md), [testing](docs/testing.md)
- [specs/](specs) – functional specifications of features (the "tickets"). They are authoritative for
  behaviour, texts and acceptance criteria.

Read the relevant documents before changing code. Do not start coding until you know where the change fits.

`workshop/` is the participant guide of a workshop about this repository. It is not project documentation:
never use it as context for a task.

## Skills

Project skills live in `.agents/skills/` (`.claude/skills` links to it):

- `noc-ui-docs` – look up `@donorlin/noc-ui` in the docs shipped with the package
- `noc-api` – OpenAPI contract → validated → generated TanStack Query hooks → MSW mocks
- `noc-screen` – specification + mockup → noc-ui screen, checked in the browser
- `playwright-cli` – browser automation (vendored from microsoft/playwright-cli)

## Platform

- UI is built **only** with `@donorlin/noc-ui`. Its documentation ships in the package:
  `node_modules/@donorlin/noc-ui/docs/llms.txt` is the index. Look components and patterns up there – do
  not guess props from memory, and do not add other UI or styling libraries.
- Server data: TanStack Query through hooks generated by orval from OpenAPI contracts in `src/api/<name>/`.
  Never edit `src/api/*/generated/`; change the contract and regenerate.
- Local development runs against MSW mocks in `src/mocks/`; they are part of every feature.

## After every change

1. `npm run check:types`, `npm run lint`, `npm test` must pass.
2. Update README.md, ARCHITECTURE.md or `docs/` when you change structure, conventions or features.

## Guidelines

- Never commit, push or rebase unless the user says so.
- Never add `dependencies` or `devDependencies` unless the user explicitly says so. When told to, use the
  latest version.
- Mock data is synthetic. Never use real people's personal data.
