## Skills

Project skills live in `.agents/skills/` (`.claude/skills` is a symlink to it):

- `noc-platform-docs` – look up `@noc/platform` in the docs shipped with the package
- `noc-api` – OpenAPI contract → validated → generated TanStack Query hooks → MSW mocks
- `noc-screen` – specification + mockup → screen built with @noc/platform, checked in the browser
- `playwright-cli` – browser automation (vendored from microsoft/playwright-cli); run it as
  `npx playwright cli …` – `playwright` is a dev dependency; if its browser is missing, install it with
  `npx playwright install chromium`

## Platform

- UI is built **only** with `@noc/platform`, the platform library in `packages/platform` (an npm workspace,
  consumed as source – no build). Its documentation: `packages/platform/docs/llms.txt` is the index. Look components and patterns up there – do
  not guess props from memory, and do not add other UI or styling libraries.
- Server data: TanStack Query through hooks generated by orval from OpenAPI contracts in `src/api/<name>/`.
  Never edit `src/api/*/generated/`; change the contract and regenerate.
- Local development runs against MSW mocks in `src/mocks/`; they are part of every feature.

## After every change

1. `npm run check:types`, `npm run lint`, `npm test` must pass.
2. Update README.md, ARCHITECTURE.md or `docs/` when you change structure, conventions or features.

## Guidelines

- Never commit, push or rebase unless the user says so.
- Never change `packages/platform` while working on a feature – it is the platform team's library. If it lacks
  something, say so.
- Never add `dependencies` or `devDependencies` unless the user explicitly says so. When told to, use the
  latest version.
- Mock data is synthetic. Never use real people's personal data.
